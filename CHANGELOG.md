# Changelog — Cloudie

## 0.1.0 - Unreleased

### Added

- Core: NetEase weapi/eapi encryption, client with cookie jar and overseas `X-Real-IP`, typed API (login QR, account,
  playlists, daily songs, recommendations, toplists, playlist/album/artist details, song URLs, lyrics, search).
- Core: LRC/YRC lyrics parser with translations, gray-track unlock (pyncmd, Navidrome/Subsonic) with strict matching,
  settings model, playback queue with shuffle/repeat; 31 unit tests.
- App: WinUI 3 shell with sidebar (推荐 / 每日推荐 / 歌单), title-bar search, player bar, immersive now-playing page
  with artwork-tinted backdrop and synced lyrics, home / track-list / search / settings pages, QR login dialog,
  system media transport controls.
- App: listening-history reporting (scrobble) with a setting, title-bar account menu (QR login / logout), search
  suggestions, artist pages list the artist's albums, "view artist / view album" context actions, keyboard
  shortcuts (Space, Ctrl+←/→, Ctrl+L, Ctrl+F, Esc), update check against GitHub Releases with a status-bar offer.
- Build: GitHub Actions compiles and publishes unpackaged x64/ARM64 zips; the version is stamped from the tag
  (`0.1.0-ci.N` for other builds) and shown in Settings → 关于.
- App: 心动模式 from the liked-songs page (button, or a row's context menu); the player bar shows a mode badge.
- App: create (with a private option), rename and delete own playlists from the sidebar ("新建歌单" row, context
  menu) and from the playlist page; the sidebar highlight now follows the page, including after Back.
- App: 私人 FM page (start, dislike, like, play/pause, next; the queue refills itself), queue and position
  restored at start-up (paused, URL fetched on play), playlist subscribe / unsubscribe, "添加到歌单" submenu and
  "从歌单中移除" on own playlists, window size / position / maximized state remembered with a 960×600 minimum.
- Core: personal FM and playlist endpoints, `PlaybackStore` (queue.json + playback.json), `PlaybackQueue.Restore`,
  `WindowPlacement` setting with display fitting; 63 unit tests.
- App: first on-device pass (WSL → Windows build loop in `scripts/wsl-dev.sh`): queue flyout marks and scrolls to
  the current song, row context menus open anywhere on the row, list pages get a 重试 button and Chinese error
  text, the daily page shows a cover, sidebar names trim with an ellipsis, icon buttons carry automation names,
  the navigation pane compacts on narrow windows, the now-playing artwork scales instead of cropping, the minimum
  window size is DPI-aware, and the progress slider no longer snaps back while dragged.

- App: 定位到正在播放. On playlist / album / artist / daily pages a round button floats at the bottom right of
  the list whenever the playing song is in it but its row has scrolled out of view; it brings the row to the
  middle of the view.
- App: an icon. A gold cloud with an eighth note cut out of it on a dark rounded tile, generated by
  `scripts/make-icons.cs` (SkiaSharp, `dotnet run`) into the tile PNGs, `Cloudie.png` for the title bar,
  `Cloudie.ico` for the exe and the window (`AppWindow.SetIcon`, so the taskbar and Alt+Tab show it when
  unpackaged) and `Logo.svg`.
- App: cover cards (`CoverCard`) on the home, search and artist pages: the stock GridView hover box is gone;
  hovering lifts the cover with a Composition scale animation, dims it slightly and fades in a play disc. The
  item container keeps keyboard focus visuals only. The stray "空格键" accelerator tooltip over the content is
  hidden.
- App: 歌曲预热. Three seconds into a song the next one's URL is resolved in the background (NetEase first,
  then the unlock sources); thirty seconds before the end its stream is opened too, so the switch needs no
  network round trip. The entry follows shuffle / 下一首播放 / FM refills, is dropped when the quality setting
  changes or after ten minutes, and a pre-opened stream that fails gets one cold retry. Core gains
  `PlaybackQueue.PeekNext` and `ResolvedMedia`; 68 unit tests.

### Fixed

- Core: NetEase answers `personalized/playlist` with `"playCount": 1.2345678E7`; every `int`/`long` field now
  accepts floats, strings and booleans instead of failing the whole response.
- App: switching the theme (or the audio quality) in Settings re-entered the two-way bound setter until the stack
  overflowed and the app vanished.
- App: the previous song kept playing while the next URL was fetched, and its position was reported as the new
  song's listening time (songs without a source, or skipped while loading, were scrobbled with the old song's
  seconds); a queue with nothing playable no longer cycles forever.
- App: the home page loaded signed out at start-up and again a second later once the session was restored; the
  theme brushes now live inside the theme dictionaries so controls stop mixing light and dark values.
- App: scrubbing the scrollbar of a long list queued a cover download for every row passed, so the rows you
  landed on waited behind hundreds of requests. Row covers now load in `x:Phase` 2 (album text in phase 1),
  which the ListView skips for rows recycled before they settle, and `CoverCache` keeps decoded covers in a
  64 MB least-recently-used store (failed downloads are dropped and retried, decode size pinned to the
  requested size) instead of a counter that wiped everything at 1024 entries.
- App: long lists (the 1472-song liked list) showed grey blocks while scrolling and stuttered: the ListView's
  scrolling placeholders are off, the row context menu is one shared MenuFlyout instead of nine items plus
  icons built for every realised row, cover BitmapImages are cached by URL so recycled rows do not decode the
  same cover again, and the locate button's scroll check no longer scans every row.
- App: Media Foundation reports one playback failure several times; each report skipped a song, so one bad
  stream threw away the next three as well. A failure is now handled once per loaded source (and never
  attributed to the source that replaced it), is logged with its error kind and HRESULT, is never scrobbled,
  and a restored session whose file cannot seek to the saved position starts from the beginning instead of
  being skipped.
